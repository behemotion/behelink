# behelink Telegram Webhook Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a behetask-server behind arbitrary NAT receive Telegram updates, by giving behelink a public webhook ingress that durably queues update payloads for the instance to long-poll and ack.

**Architecture:** Store-and-forward. A public `POST /v1/tg/{link_id}/{path_token}` validates an unguessable path token, commits the raw body to a SQLite queue, and only then answers Telegram `200`. The NAT'd behetask-server long-polls `GET /v1/links/{id}/telegram/updates`, processes, and `POST`s an ack that deletes through a sequence number. behelink never sees the bot token.

**Tech Stack:** Python 3.12, FastAPI, sqlite3 (stdlib), pydantic-settings, pytest.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-behelink-telegram-webhook-relay-design.md`. Read it before Task 1.
- All endpoints under bare `/v1`. Errors are RFC 9457 via `errors.ProblemError` — never raise bare `HTTPException`.
- Env prefix `BEHELINK_`; all new settings go in `config.py` with defaults.
- Time comes from `clock.now()`, never `time.time()` directly — tests monkeypatch it.
- Tokens are generated by `tokens.generate_token(prefix)` and stored **hashed** via `tokens.hash_token`; compared with `tokens.verify_token`. Never store or log a token in cleartext.
- One module per concern in `src/behelink/`, one test file per module in `tests/`.
- Unknown link, disabled relay, and bad token must be **byte-identical** `404`s (use the existing `_not_found(link_id)` helper) so the ingress cannot be used to enumerate link IDs.
- Run the suite with `uv run pytest -q` from the repo root.
- Conventional Commit prefixes on every commit.

### Task 1: Schema and `links` migration

**Files:**
- Modify: `src/behelink/db.py`
- Test: `tests/test_telegram_queue_store.py`

**Interfaces:**
- Consumes: `db.connect(path)`, `db.Link`, `db.insert_link`, `db.get_link`
- Produces: `telegram_updates` table; `Link.telegram_path_token_hash: str | None`, `Link.telegram_relay_enabled_at: float | None`, `Link.telegram_dropped_total: int`

**Why a migration is required:** `db.connect()` runs `CREATE TABLE IF NOT EXISTS links`, which does **not** add columns to an already-existing table. The live behelink database has rows in it. Without an `ALTER TABLE` pass, every new column silently fails to appear.

**The trap:** `db.get_link` builds its result with `Link(**dict(row))`. The moment you add a column to `links` without adding a matching field to the `Link` dataclass, every existing call raises `TypeError: unexpected keyword argument`. Add the dataclass fields in the same commit.

```python
@dataclass
class TelegramUpdate:
    seq: int
    link_id: str
    payload: bytes
    secret_header: str | None
    received_at: float


def enqueue_update(
    conn: sqlite3.Connection,
    link_id: str,
    payload: bytes,
    secret_header: str | None,
    received_at: float,
    max_depth: int,
) -> int | None:
    """Commit one update. Returns its seq, or None when the queue is full.

    The depth check is advisory: two concurrent ingress requests can both pass
    it and overshoot max_depth by the number of in-flight requests. That is
    bounded by the ingress rate limiter and costs a few extra rows, whereas
    holding a write lock across the check would serialize every delivery.
    """
    (depth,) = conn.execute(
        "SELECT COUNT(*) FROM telegram_updates WHERE link_id = ?", (link_id,)
    ).fetchone()
    if depth >= max_depth:
        return None
    cursor = conn.execute(
        "INSERT INTO telegram_updates (link_id, payload, secret_header, received_at)"
        " VALUES (?, ?, ?, ?)",
        (link_id, payload, secret_header, received_at),
    )
    conn.commit()
    return int(cursor.lastrowid)


def fetch_updates(
    conn: sqlite3.Connection, link_id: str, limit: int
) -> list[TelegramUpdate]:
    rows = conn.execute(
        "SELECT seq, link_id, payload, secret_header, received_at FROM telegram_updates"
        " WHERE link_id = ? ORDER BY seq LIMIT ?",
        (link_id, limit),
    ).fetchall()
    return [TelegramUpdate(**dict(row)) for row in rows]


def ack_updates(conn: sqlite3.Connection, link_id: str, through_seq: int) -> int:
    cursor = conn.execute(
        "DELETE FROM telegram_updates WHERE link_id = ? AND seq <= ?",
        (link_id, through_seq),
    )
    conn.commit()
    return cursor.rowcount


def queue_stats(
    conn: sqlite3.Connection, link_id: str
) -> tuple[int, int | None, float | None]:
    row = conn.execute(
        "SELECT COUNT(*) AS depth, MIN(seq) AS oldest, MAX(received_at) AS last"
        " FROM telegram_updates WHERE link_id = ?",
        (link_id,),
    ).fetchone()
    return int(row["depth"]), row["oldest"], row["last"]


def sweep_expired(conn: sqlite3.Connection, cutoff: float) -> int:
    """Delete rows older than cutoff, crediting each link's dropped counter."""
    rows = conn.execute(
        "SELECT link_id, COUNT(*) AS n FROM telegram_updates"
        " WHERE received_at < ? GROUP BY link_id",
        (cutoff,),
    ).fetchall()
    total = 0
    for row in rows:
        conn.execute(
            "UPDATE links SET telegram_dropped_total = telegram_dropped_total + ?"
            " WHERE id = ?",
            (row["n"], row["link_id"]),
        )
        total += int(row["n"])
    conn.execute("DELETE FROM telegram_updates WHERE received_at < ?", (cutoff,))
    conn.commit()
    return total


def enable_telegram_relay(
    conn: sqlite3.Connection, link_id: str, path_token_hash: str, enabled_at: float
) -> None:
    conn.execute(
        "UPDATE links SET telegram_path_token_hash = ?, telegram_relay_enabled_at = ?"
        " WHERE id = ?",
        (path_token_hash, enabled_at, link_id),
    )
    conn.commit()


def disable_telegram_relay(conn: sqlite3.Connection, link_id: str) -> None:
    conn.execute(
        "UPDATE links SET telegram_path_token_hash = NULL,"
        " telegram_relay_enabled_at = NULL WHERE id = ?",
        (link_id,),
    )
    conn.execute("DELETE FROM telegram_updates WHERE link_id = ?", (link_id,))
    conn.commit()
```

```python
# src/behelink/telegram_queue.py
"""In-process wakeup signalling for the Telegram update long-poll.

Holds no payloads — the queue itself is durable in SQLite (`db.telegram_updates`).
This exists so a consumer blocked in `GET .../telegram/updates` wakes the moment
an update is committed, instead of polling the database on a timer.
"""

import asyncio


class TelegramQueueWaiter:
    def __init__(self) -> None:
        self._events: dict[str, asyncio.Event] = {}

    def _event_for(self, link_id: str) -> asyncio.Event:
        return self._events.setdefault(link_id, asyncio.Event())

    def notify(self, link_id: str) -> None:
        self._event_for(link_id).set()

    async def wait(self, link_id: str, timeout: float) -> None:
        event = self._event_for(link_id)
        if event.is_set():
            event.clear()
            return
        event.clear()
        try:
            await asyncio.wait_for(event.wait(), timeout=timeout)
        except TimeoutError:
            return
        event.clear()
```

        settings.telegram_webhook_rate_per_minute, window_seconds=60.0
    )
    app.state.telegram_queue_waiter = TelegramQueueWaiter()

    @app.post("/v1/tg/{link_id}/{path_token}")
    async def telegram_ingress(
        link_id: str,
        path_token: str,
        request: Request,
        conn: sqlite3.Connection = Depends(get_conn),
    ) -> JSONResponse:
        if not settings.telegram_relay_enabled:
            raise _not_found(link_id)
        link = db.get_link(conn, link_id)
        # Unknown link, relay disabled, and bad token are one indistinguishable
        # 404 — this endpoint is unauthenticated and public, so distinguishing
        # them would let anyone enumerate link IDs.
        if (
            link is None
            or link.telegram_path_token_hash is None
            or not tokens.verify_token(path_token, link.telegram_path_token_hash)
        ):
            raise _not_found(link_id)
        if not app.state.telegram_webhook_limiter.allow(link_id):
            raise ProblemError(
                429,
                "rate_limited",
                "Too Many Requests",
                "webhook rate limit exceeded for this link",
                headers={"Retry-After": "60"},
            )
        payload = await request.body()
        if len(payload) > settings.telegram_max_payload_bytes:
            raise ProblemError(
                413, "usage", "Payload Too Large", "update exceeds configured maximum"
            )
        seq = db.enqueue_update(
            conn,
            link_id,
            payload=payload,
            secret_header=request.headers.get("X-Telegram-Bot-Api-Secret-Token"),
            received_at=clock.now(),
            max_depth=settings.telegram_queue_max_depth,
        )
        if seq is None:
            # 503 (not 200) so Telegram retries. Answering 200 here would make
            # this a silent, permanent loss of a user's command.
            raise ProblemError(
                503,
                "unavailable",
                "Service Unavailable",
                "update queue is full; retry later",
                headers={"Retry-After": "10"},
            )
        app.state.telegram_queue_waiter.notify(link_id)
        return JSONResponse({"ok": True})

    async def telegram_updates(
        link_id: str,
        request: Request,
        wait: float = Query(default=0.0, ge=0.0),

**Known limitation, stated rather than hidden:** `enable` is idempotent only while the process lives, because the cleartext token is cached in `app.state` and the database keeps only its hash. After a behelink restart, a re-enable mints a fresh token and the caller must re-register the new URL with Telegram. behetask's consumer handles this by treating `enableTelegramRelay` as authoritative on every startup and calling `setWebhook` with whatever URL comes back.
